# Визуализатор графа зависимостей NuGet

Практическая работа №2 по дисциплине «Конфигурационное управление», вариант 28.

## Общее описание

Консольное приложение (CLI) на C++17 для визуализации графа зависимостей
пакетов менеджера NuGet (.NET). Готовые менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются: только стандартная
библиотека C++.

Что умеет приложение:

* получать данные о пакетах из репозитория NuGet по протоколу NuGet V3;
* строить полный граф зависимостей с учётом транзитивности — обходом в
  глубину (DFS) **без рекурсии**;
* находить циклические зависимости и корректно их обрабатывать;
* работать с тестовым репозиторием — графом пакетов из текстового файла;
* выводить порядок загрузки зависимостей;
* формировать описание графа на языке **Graphviz** (DOT) и сохранять
  изображение графа в файл **SVG**;
* выводить зависимости в виде **ASCII-дерева**.

## Функции и настройки

### Параметры командной строки

| Параметр | Обязательный | По умолчанию | Что задаёт |
|---|---|---|---|
| `--package ИМЯ` | да | — | имя анализируемого пакета |
| `--repo URL_ИЛИ_ПУТЬ` | нет | `https://api.nuget.org/v3/index.json` | URL репозитория NuGet или путь к файлу тестового репозитория |
| `--test-mode` | нет | выключен | режим работы с тестовым репозиторием |
| `--output ФАЙЛ` | нет | `graph.svg` | имя файла с изображением графа |
| `--ascii-tree` | нет | выключен | вывод зависимостей в виде ASCII-дерева |
| `--load-order` | нет | выключен | вывод порядка загрузки зависимостей вместо списка связей |

Значение можно писать через пробел (`--package Serilog`) или через знак
равенства (`--package=Serilog`).

### Ошибки

Любая ошибка выводится с префиксом `error:`, программа завершается с кодом 1.

| Источник | Ошибки |
|---|---|
| `--package` | не задан; нет значения; пустой; недопустимые символы; длиннее 100 символов; в тестовом режиме — не большие латинские буквы |
| `--repo` | нет значения; пустой; не `http://` или `https://` адрес; недопустимые символы; в тестовом режиме — не задан или файл не существует |
| `--output` | нет значения; расширение не `.svg`; папка для файла не существует |
| флаги `--test-mode`, `--ascii-tree`, `--load-order` | передано значение |
| любой параметр | неизвестный; задан дважды; аргумент без `--` |
| репозиторий NuGet | нет связи (или не установлен `curl`); пакет или версия не найдены; нет версии под диапазон; код ошибки сервера; повреждённый JSON или XML |
| тестовый файл | строка без двоеточия; неверное имя пакета (с номером строки); пакет описан дважды; анализируемого пакета нет в файле |
| сохранение | не удалось записать `.dot` или `.svg`; ошибка программы `dot` |

### Как получаются зависимости из NuGet

1. По URL репозитория (`https://api.nuget.org/v3/index.json`) скачивается
   индекс сервиса — JSON со списком ресурсов. Из него берётся ресурс
   `PackageBaseAddress/3.0.0` — адрес хранилища пакетов
   (`https://api.nuget.org/v3-flatcontainer/`). URL хранилища можно указать
   и напрямую.
2. `{хранилище}/{имя}/index.json` — список версий пакета.
3. `{хранилище}/{имя}/{версия}/{имя}.nuspec` — описание пакета (XML).
   В разделе `<dependencies>` зависимости разбиты на группы по целевым
   платформам (`.NETStandard2.0`, `net8.0` и т. д.).
4. Выбирается одна группа: `netstandard2.0` (подходит большинству проектов),
   иначе `netstandard2.1`, иначе зависимости без группы, иначе первая группа.

Имена пакетов в адресах пишутся маленькими буквами — так требует протокол.

В стандартной библиотеке C++ нет ни HTTP, ни JSON, ни XML, поэтому:

| Задача | Решение |
|---|---|
| HTTP-запрос | системная утилита `curl` (есть в Linux, macOS и Windows 10+), запускается через `popen`; она только скачивает текст, код ответа программа проверяет сама |
| JSON | собственный разборщик `src/json.cpp` (рекурсивный спуск по грамматике JSON) |
| XML | собственный разборщик `src/xml.cpp`: теги, атрибуты, комментарии, CDATA, `&amp;` и т. п. |

### Выбор версий

* Анализируемый пакет — последняя стабильная версия.
* Зависимость — **наименьшая** версия, подходящая под диапазон из `.nuspec`
  (правило NuGet «lowest applicable version»): `1.0` — 1.0 или новее,
  `[1.0, 2.0)` — от 1.0 включительно до 2.0 не включая, `(1.0,)` — новее 1.0,
  `[1.0]` — ровно 1.0, `(, 2.0]` — до 2.0 включительно. Пререлизы не
  берутся, если граница сама не пререлиз.
* Если пакет встречается несколько раз, используется диапазон, встреченный
  первым.
* Имена пакетов NuGet не зависят от регистра: `lib.c` и `Lib.C` — один пакет.

### Построение графа: DFS без рекурсии

Граф строится обходом в глубину **без рекурсии** — с явным стеком
(`src/graph.cpp`, функция `buildGraph`). В стеке лежат пары «пакет, номер
следующей зависимости»; у каждого пакета есть состояние «в обработке»
(лежит на стеке) или «готов». На каждом шаге берётся верхний пакет и его
следующая зависимость:

* зависимость ещё не встречалась — её зависимости запрашиваются, она кладётся
  на стек;
* зависимость «готова» — пропускается (каждый пакет запрашивается один раз,
  даже если от него зависят несколько пакетов);
* зависимость «в обработке» — это **цикл**: путь от неё по стеку до текущего
  пакета запоминается, дальше по этой связи обход не идёт, поэтому программа
  не зацикливается.

Без рекурсии глубина графа ограничена только памятью: цепочка из 200 000
пакетов обрабатывается без переполнения стека вызовов (есть unit-тест).

Источник данных скрыт за интерфейсом `DependencySource`; его реализуют
`NuGetSource` (репозиторий NuGet) и `LocalRepository` (тестовый файл).

### Тестовый режим

С параметром `--test-mode` в `--repo` передаётся путь к файлу с описанием
графа. Пакеты называются большими латинскими буквами:

```
# комментарий
A: B C      пакет A зависит от B и C
B: D
C: D
D:          у D нет зависимостей
```

Пакет, упомянутый как зависимость, но не описанный отдельной строкой,
считается пакетом без зависимостей.

| Файл в `tests/data/` | Случай |
|---|---|
| `simple.txt` | общая зависимость (ромб): D нужен и B, и C |
| `deep.txt` | несколько уровней и общих зависимостей |
| `cycle.txt` | цикл A → B → C → A |
| `self_loop.txt` | пакет зависит сам от себя |
| `two_cycles.txt` | два независимых цикла |
| `bad_name.txt`, `bad_format.txt` | ошибки в файле |

### Порядок загрузки

С параметром `--load-order` выводится порядок, в котором нужно загрузить
пакеты, чтобы к моменту загрузки каждого пакета все его зависимости уже были
загружены. Порядок строит функция `loadOrder` (`src/graph.cpp`) — тоже
обходом в глубину без рекурсии: пакет добавляется в список, когда обработаны
все его зависимости (post-order). Это топологическая сортировка графа. Если в
графе есть цикл, строгого порядка не существует: связь, замыкающая цикл,
пропускается, и программа сообщает об этом строкой `Note:`.

### Сравнение с менеджером пакетов NuGet

Проверка: создать консольный проект .NET, добавить пакет и вывести все его
зависимости штатной командой:

```
dotnet new console -o demo
cd demo
dotnet add package Serilog.Sinks.Console
dotnet list package --include-transitive
```

Результаты проверки (ноябрь 2026, консольный проект .NET 10):

| Пакет | `dotnet list package` | Наша программа |
|---|---|---|
| `Serilog.Sinks.Console 6.1.1` | 2 пакета: сам пакет и `Serilog 4.0.0` | 9 пакетов: те же 2 и ещё 7 пакетов `System.*` (`System.Memory`, `System.Buffers`, `System.Threading.Channels` и др.) |
| `Microsoft.Extensions.Logging 10.0.14` | 6 пакетов (`Logging`, `Logging.Abstractions`, `DependencyInjection`, `DependencyInjection.Abstractions`, `Options`, `Primitives`) | 14 пакетов: те же 6 и ещё `Microsoft.Bcl.AsyncInterfaces`, `System.ComponentModel.Annotations` и 6 пакетов `System.*` |
| `Microsoft.Extensions.Http 10.0.14` | 13 пакетов | 16 пакетов: 8 общих и 8 пакетов для старых платформ; нет 5 пакетов `Configuration`, `Configuration.Binder`, `Diagnostics`, `Diagnostics.Abstractions`, `Options.ConfigurationExtensions` |

Версии общих пакетов совпадают. Состав и порядок различаются, потому что:

1. **Целевая платформа — главная причина.** NuGet берёт группу зависимостей
   под платформу проекта (`net10.0`), наша программа — группу
   `netstandard2.0`. Пакеты `System.Memory`, `System.Buffers`,
   `Microsoft.Bcl.AsyncInterfaces` и т. п. — дополнения для старых платформ;
   в .NET 10 всё это встроено. И наоборот: у `Microsoft.Extensions.Http`
   для `net10.0` есть зависимости, которых нет в группе `netstandard2.0`.
2. **Порядок вывода.** NuGet не выводит порядок загрузки: пакеты
   скачиваются параллельно, а `dotnet list package` перечисляет их по
   алфавиту. Наша программа выводит топологический порядок.
3. **Версии.** NuGet применяет правила «direct dependency wins» и «cousin
   dependencies» (берётся наибольшая из нижних границ). Наша программа берёт
   наименьшую версию по диапазону, встреченному первым, поэтому для общей
   зависимости версия может оказаться ниже. В проверенных пакетах версии
   совпали.
4. **Циклы.** Для NuGet цикл — ошибка `NU1108`. Наша программа сообщает о
   цикле и продолжает работу.

### Визуализация

При каждом запуске сохраняются два файла:

* `{имя}.dot` — описание графа на языке диаграмм **Graphviz** (функция
  `toDot` в `src/render.cpp`). Узел — пакет (имя и версия на двух строках),
  стрелка — от пакета к его зависимости. Анализируемый пакет выделен цветом,
  связь, замыкающая цикл, — красным пунктиром.
* `{имя}.svg` — изображение графа (имя задаётся параметром `--output`).
  Его рисует программа `dot` из пакета Graphviz (ищется в папках `PATH`,
  запускается командой `dot -Tsvg имя.dot -o имя.svg`). Если Graphviz не
  установлен, используется встроенный рисовальщик (`src/svg.cpp`): пакеты
  располагаются по уровням — по расстоянию от анализируемого пакета; стрелки
  вниз — прямые, в своём ряду — дуги снизу, обратные связи циклов — дуги
  справа. В выводе указано, чем нарисован файл.

Пример файла `.dot` для `tests/data/simple.txt`:

```
digraph dependencies {
    rankdir=TB;
    node [shape=box, style="rounded,filled", fillcolor="#f2f5fa", fontname="Helvetica"];
    "A" [label="A", fillcolor="#cfe0f7", penwidth=2];
    "B" [label="B"];
    "D" [label="D"];
    "C" [label="C"];
    "A" -> "B";
    "A" -> "C";
    "B" -> "D";
    "C" -> "D";
}
```

С параметром `--ascii-tree` зависимости выводятся деревом из символов ASCII
(функция `asciiTree`, тоже без рекурсии — со стеком). Поддерево пакета,
который уже был показан, не повторяется — у него пометка `(see above)`;
пакет, замыкающий цикл, помечен `(cycle)`:

```
A
+-- B
|   \-- C
|       \-- B (cycle)
\-- D
    \-- E
        \-- F
            \-- D (cycle)
```

Установка Graphviz (необязательно): `sudo apt install graphviz` (Linux),
`winget install graphviz` (Windows).

#### Сравнение со штатными инструментами

Отдельного инструмента для рисования графа у NuGet нет. Штатные способы
посмотреть зависимости: Visual Studio («Обозреватель решений» →
«Зависимости» → «Пакеты»), `dotnet list package --include-transitive`,
страница пакета на nuget.org (вкладка «Dependencies»). Отличия:

1. Visual Studio показывает дерево, в котором общая зависимость повторяется
   под каждым пакетом. Наш граф показывает каждый пакет один раз, а
   ASCII-дерево заменяет повтор пометкой `(see above)`.
2. Штатные инструменты показывают версии, выбранные NuGet для всего
   проекта; у нас версия выбирается для каждой зависимости по её диапазону.
3. Штатные инструменты показывают зависимости под платформу проекта,
   nuget.org — для всех платформ сразу; у нас — группа `netstandard2.0`.
4. Циклов в штатных инструментах не бывает: NuGet не восстанавливает такой
   проект. Наш граф показывает цикл красной пунктирной стрелкой.

## Сборка и запуск тестов

Нужны компилятор C++17 (`g++`; на Windows — MinGW-w64) и утилита `curl`
(для работы с сетью). Graphviz — по желанию.

```
./run.sh --package Serilog.Sinks.Console --ascii-tree    # Linux, macOS
run.bat --package Serilog.Sinks.Console --ascii-tree     # Windows

./test.sh                                                # unit-тесты, Linux, macOS
test.bat                                                 # unit-тесты, Windows
```

Скрипты `run.*` и `test.*` собирают программу заново при каждом запуске,
поэтому после переключения на другой коммит работает код именно этого
коммита. Ручная сборка: `g++ -std=c++17 -O2 -o bin/depviz src/*.cpp`.

Unit-тесты используют собственный минимальный фреймворк `tests/test.h`
(макросы `TEST`, `CHECK`, `CHECK_EQ`, `CHECK_THROWS`, `CHECK_CONTAINS`).
Программа тестов выводит результат каждого теста и итог
`Ran N tests: N passed, 0 failed`.

| Файл тестов | Что проверяет |
|---|---|
| `tests/test_config.cpp` | значения по умолчанию, все параметры, ошибки каждого параметра |
| `tests/test_json.cpp`, `tests/test_xml.cpp` | разбор JSON и XML, ошибки в тексте |
| `tests/test_versions.cpp` | сравнение версий, пререлизы, последняя стабильная, диапазоны и наименьшая подходящая версия |
| `tests/test_nuspec.cpp` | группы платформ, старый формат, выбор группы |
| `tests/test_nuget.cpp` | индекс сервиса, коды ответа, ошибка связи, граф по данным NuGet, регистр имён |
| `tests/test_graph.cpp` | транзитивные зависимости, порядок DFS, циклы, петля, цепочка из 200 000 пакетов |
| `tests/test_local_repo.cpp` | файл тестового репозитория, ошибки с номером строки, графы из `tests/data` |
| `tests/test_order.cpp` | порядок загрузки: цепочка, ромб, циклы, зависимости раньше пакетов |
| `tests/test_render.cpp` | **описание на языке Graphviz, выделение корня и циклов, экранирование, ASCII-дерево** |
| `tests/test_svg.cpp` | **встроенный рисовальщик (SVG проверяется разбором как XML), рисование через Graphviz, ошибки записи** |
| `tests/test_app.cpp` | запуск приложения целиком: граф, порядок загрузки, **файлы `.dot` и `.svg`, ASCII-дерево**, ошибки |

Тесты не обращаются к интернету: сервер NuGet подменяется объектом
`FakeFetcher` (`tests/fake_nuget.h`). Тесты Graphviz выполняются, только
если программа `dot` установлена.

## Структура проекта

```
src/
  main.cpp            точка входа
  app.h/.cpp          запуск приложения, вывод результата
  config.h/.cpp       параметры командной строки и их проверка
  graph.h/.cpp        построение графа (DFS без рекурсии), циклы, порядок загрузки
  local_repo.h/.cpp   тестовый репозиторий из текстового файла
  nuget.h/.cpp        репозиторий NuGet, выбор версий
  nuspec.h/.cpp       зависимости из файла .nuspec
```
